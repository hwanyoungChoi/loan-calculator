# 정렬 방향 전환·정렬 기억·예산 계정 저장

## 목표

저장 목록을 매일 여는 사람이 정렬을 반대로 볼 수 있고, 다시 열 때 마지막에 보던 정렬·보기로 시작한다. 로그인한 사람은 어느 브라우저(카카오톡 인앱, 사파리)에서 열어도 같은 예산을 본다.

## 사용자 시나리오

1. 자기자금순(적은 순 ↑)으로 보다가 [자기자금순]을 한 번 더 누르면 많은 순(↓)이 된다. 또 누르면 다시 적은 순이다. 최근 저장순·가나다순도 같다.
2. 가나다순 ↓, 간단히로 바꾸고 앱을 닫는다. 다음 날 계산 탭에서 [저장 목록]을 누르면 가나다순 ↓, 간단히로 열린다. 로그인에서 돌아올 때, 공유받은 매물을 추가한 뒤에도 같다.
3. 카카오톡 인앱 브라우저에서 로그인한 채 예산을 3억으로 정한다. 사파리에서 같은 계정으로 로그인해 열면 3억이 보인다.
4. 로그인 전에 이 기기에 예산 2억을 넣어 둔 사람이 처음 로그인하면 계정에 예산이 없으므로 2억이 계정에 올라간다. 계정에 이미 3억이 있으면 3억이 보인다.
5. 로그아웃하면 이 기기에 저장돼 있던 예산(로그인 전 값)이 다시 보인다.

## 참고한 사례

- **Google Drive 목록 보기**: 정렬 기준 머리글을 누른 뒤 옆의 위·아래 화살표로 순서를 뒤집는다. 정렬 설정은 저장돼 다음에 그대로 열린다(도움말 "sorting preferences will be saved"). 이름은 오름차순, 수정 날짜는 최신이 먼저인 내림차순이 기본이다. → 기준마다 기본 방향을 두고, 화살표로 방향을 보이고, 마지막 설정을 기억한다. https://support.google.com/drive/answer/2375177
- **WAI-ARIA APG Sortable Table 예제**: 정렬 머리글은 버튼이고, 이미 정렬된 머리글을 다시 누르면 방향이 바뀐다. 방향은 화살표 기호와 보조기기용 이름에 함께 나온다. → "선택된 정렬을 다시 누르면 방향 전환"과 접근성 이름에 방향을 넣는 것을 가져온다. https://www.w3.org/WAI/ARIA/apg/patterns/table/examples/sortable-table/
- **Excel·Google 스프레드시트 정렬**: 빈 셀은 오름차순이든 내림차순이든 맨 뒤에 둔다. → 자기자금을 계산할 수 없는 매물(null)은 방향과 상관없이 맨 뒤에 둔다.
- **GitHub REST API 목록 조회**: 정렬 기준 `sort`와 방향 `direction=asc|desc`를 따로 둔다. → 주소에 기존 `sort`는 그대로 두고 방향 파라미터를 따로 더한다(D3). https://docs.github.com/en/enterprise/2.18/user/rest/reference/issues
- **이 프로젝트의 매물 이전(`useAccountImport`, ADR-023)**: 로그인을 확인한 직후 기기 데이터를 계정에 올리고, 이 기기에서 어느 계정으로 옮겼는지 새 localStorage 키에 기록해 다시 올리지 않는다. 서버는 `ON CONFLICT DO NOTHING`으로 이미 있는 것을 덮지 않는다. → 예산 이전도 같은 모양(새 기록 키 + 비어 있을 때만 채우는 한 문장)으로 한다.

## 범위

- 포함:
  - 정렬 3종의 방향 전환(오름·내림), 버튼의 ↑↓ 표시, 주소의 방향 파라미터
  - 마지막으로 본 정렬·방향·보기를 이 기기에 기억하고, 주소에 값이 없을 때 그 값으로 연다
  - 로그인 사용자의 예산을 계정(D1)에 저장·조회·지우기, 첫 로그인 때 기기 예산 이전, 로그아웃 때 기기 예산으로 복귀
- 범위 밖:
  - 정렬·보기 기억의 계정 동기화(기기별로 둔다)
  - 앱을 열 때 마지막 탭(계산 / 저장 목록)으로 여는 것(U3)
  - draft·실거래가 시군구의 계정 저장
  - 새 테스트 작성(qa off). 바뀐 구조로 깨지는 기존 테스트는 그 파일 담당이 고친다.

| 키                               | 형식                                                                                          | 쓰는 곳                                                                                                                                                                                   |
| -------------------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `loan-calculator/listings-view`  | `{ "sort": "ownFunds"\|"recent"\|"name", "order": "asc"\|"desc", "view": "card"\|"compact" }` | 저장 목록 화면이 실제로 보여 준 정렬·방향·보기. 필드마다 허용 목록으로 읽고, 틀린 필드만 기본값으로 본다. JSON이 아니거나 키가 없으면 전부 기본값. 쓰기는 최선(못 쓰면 이 탭에서만 유지). |
| `loan-calculator/budget-imports` | `string[]` (예산 이전을 끝낸 사용자 id)                                                       | 첫 로그인 예산 이전 기록. 형식이 틀리면 빈 배열로 본다.                                                                                                                                   |
| `loan-calculator/budget` (기존)  | 그대로 (`1~999,999,999` 정수 JSON)                                                            | 로그아웃 상태의 예산 원본. **로그인 중에는 읽기만 한다**(이전 때 읽음). 로그인 중 예산을 바꿔도 이 키는 바뀌지 않는다.                                                                    |

### D1 (D1 결정 필요 — 아래는 추천안 A 기준)

`migrations/0003_user_budget.sql`

```sql
-- 계정 예산(만원). NULL = 예산 없음. 값 검증(1~999,999,999 정수)은 서버가 한다.
ALTER TABLE users ADD COLUMN budget INTEGER;
```

- 기존 `users` 행은 모두 `budget = NULL`이 된다(= 계정에 예산 없음). 기존 `listings`·`sessions`·`shares`는 건드리지 않는다.
- 배포 순서: **원격 마이그레이션 적용 → Worker 배포**. 반대면 로그인 사용자의 예산 조회가 500이 된다.

### 타입

- `ListingSortOrder = "asc" | "desc"` (`src/lib/types/listing.ts`)
- Route listings: `{ name: "listings"; sort?: ListingSort; order?: ListingSortOrder; view?: ListingView; login?: LoginResult }` — 주소에 없거나 허용 목록 밖이면 `undefined`.

### 정렬 방향 규칙 (제안 기본값, U1·U2)

| 정렬        | 기본 방향 | asc(↑)                      | desc(↓)            | 동률·예외                                                 |
| ----------- | --------- | --------------------------- | ------------------ | --------------------------------------------------------- |
| 자기자금순  | asc       | 자기자금 적은 순(지금 동작) | 많은 순            | 자기자금 null(미확인·요건 미충족)은 방향과 상관없이 맨 뒤 |
| 최근 저장순 | desc      | `updatedAt` 오래된 순       | 최신 순(지금 동작) | —                                                         |
| 가나다순    | asc       | 가→하(지금 동작)            | 하→가              | —                                                         |

- 뒤집는 것은 첫째 기준뿐이다. 동률 처리(`createdAt` 최신 먼저, null 묶음 안의 순서)는 방향과 상관없이 지금 그대로다.
- 다른 정렬 버튼을 누르면 그 정렬의 기본 방향으로 시작한다.

### 화면 상태 결정 규칙 (D2 추천안 A)

1. 주소에 있는 값이 이긴다.
2. 주소에 없는 값은 기억(`listings-view`) → 그것도 없으면 기본값(자기자금순·asc·상세히).
3. `order`가 주소에 없을 때: 주소에 `sort`가 있으면 **그 정렬의 기본 방향**(옛 URL `?sort=name`이 지금처럼 가→하로 열림), `sort`도 없으면 기억된 방향.
4. 화면에서 정렬·방향·보기를 바꾸면 세 값을 모두 주소에 쓴다(`replace`, 히스토리 안 쌓음). 기본값이어도 생략하지 않는다.
5. 화면이 보여 준 상태(1~3으로 정한 값)를 기억에 쓴다. 그래서 탭·로그인 복귀(`/#/listings`)·공유 추가 후 이동(`PATHS.listings()`)처럼 값 없는 주소로 들어오면 마지막 상태가 된다.

예: 기억 = 가나다 ↓ 간단히 → `#/listings` 는 가나다 ↓ 간단히, `#/listings?sort=recent` 는 최근 저장 ↓(최신) 간단히, `#/listings?view=card` 는 가나다 ↓ 상세히.

## API 계약

공통 규칙은 기존과 같다(ADR-023): JSON 응답, 오류 본문 `{ error, message }`, `Cache-Control: no-store`, GET/HEAD가 아닌 요청은 `Origin`이 같은 출처가 아니면 403, 세션 쿠키 `mf_session`이 없거나 무효면 401, 본문은 스트림으로 세어 초과 시 413.

**예산 값 검증**: `Number.isInteger(v) && 1 <= v && v <= MAX_AMOUNT(999_999_999)` — 기존 `parseBudget`와 같은 범위. 한 함수 `isBudgetAmount(value: unknown): value is number`(`src/lib/utils/isBudgetAmount.ts`, DOM 타입·`@/` 별칭 없이 `./amount`만 상대 경로로 import)를 서버와 `parseBudget`가 함께 쓴다.

| Method | Path                 | 인증 | Request                                            | Response                                                                                    | 에러                                                                               |
| ------ | -------------------- | ---- | -------------------------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| GET    | `/api/budget`        | 필수 | —                                                  | 200 `{ "budget": number \| null }`                                                          | 401                                                                                |
| PUT    | `/api/budget`        | 필수 | `{ "budget": number \| null }` — `null`이면 지운다 | 200 `{ "budget": number \| null }` (저장된 값)                                              | 400 invalidParams(키 없음, 범위 밖, 정수 아님, 문자열 등), 401, 403, 413(1KB 초과) |
| POST   | `/api/budget/import` | 필수 | `{ "budget": number }` (null 불가)                 | 200 `{ "budget": number }` (**계정의 현재 값**: 비어 있었으면 보낸 값, 이미 있었으면 그 값) | 400, 401, 403, 413(1KB 초과)                                                       |

- PUT은 `UPDATE users SET budget = ?2 WHERE id = ?1`.
- import는 한 문장 `UPDATE users SET budget = COALESCE(budget, ?2) WHERE id = ?1 RETURNING budget`. 계정 값이 있으면 덮지 않는다(두 기기가 동시에 첫 로그인해도 먼저 온 값 하나만 남음).
- 400 예: `{}`, `{"budget":0}`, `{"budget":1000000000}`, `{"budget":1.5}`, `{"budget":"30000"}`, `{"budget":true}`, import에 `{"budget":null}`. 경계 `1`·`999999999`는 200. `30000.0`은 JSON 파싱 후 정수라 200(기존 `parseBudget`와 같음).
- 공유 타입은 `src/lib/types/account.ts`에 더한다: `BudgetResponse = { budget: number | null }`, `BudgetRequest = { budget: number | null }`, `ImportBudgetRequest = { budget: number }`, `ImportBudgetResponse = { budget: number }`.

## 화면

### 저장 목록 `#/listings` — 정렬

- 정렬 그룹은 3개 버튼 그대로, 선택된 버튼에만 방향 화살표(↑ asc / ↓ desc)를 붙인다. 접근성 이름에 방향을 글로 넣는다(예: "자기자금순, 적은 금액부터" / "최근 저장순, 최신부터" / "가나다순, 가에서 하").
- 선택된 버튼을 다시 누르면(마우스·터치·키보드 Space/Enter) 방향이 바뀐다. 주의: 지금 `ChoiceGroup`은 네이티브 라디오라 **이미 선택된 라디오를 누르면 `change`가 오지 않는다**. 저장 목록 정렬만 `aria-pressed` 버튼 그룹으로 바꾸거나 `click`으로 처리한다(fe 판단, 다른 곳의 `ChoiceGroup`은 그대로).
- 보기(상세히/간단히)는 지금 그대로, 바꾸면 기억된다.
- 매일 쓰는 사람의 불편: 방향을 바꿔도 스크롤 위치·열린 메모 편집이 사라지지 않게 지금처럼 `replace`로만 주소를 바꾼다. 카드 → 계산 → 뒤로 가기는 주소에 세 값이 다 있어 같은 정렬로 돌아온다.

### 저장 목록 — 내 예산 줄(`BudgetBar`)

출처는 매물 목록과 같은 출처 상태(`loading | loggedOut | loggedIn | error`)를 따른다.

| 상태                                               | 예산 줄                                                                                                          |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| loggedOut                                          | 지금 그대로(기기 예산, `loan-calculator/budget`)                                                                 |
| loading(`/api/me` 전·예산 이전 중·예산 첫 조회 중) | "예산을 불러오는 중"과 [예산 입력/수정] 비활성. 기기 예산을 먼저 그리지 않는다(깜빡임 방지). 예산 초과 표시 없음 |
| loggedIn, 조회 성공                                | 계정 예산. 창 포커스 때 다시 조회해 다른 기기 변경을 반영                                                        |
| loggedIn, 첫 조회·이전 실패                        | "예산을 불러오지 못했습니다 [다시 시도]". 기기 예산으로 대신 보이지 않는다                                       |
| error(계정 확인 실패)                              | 예산 줄도 "계정 상태를 확인한 뒤 다시 시도해 주세요"로 막는다(계정 줄이 [다시 시도] 제공)                        |

- 로그인 중 저장 실패(네트워크·500): 폼을 닫지 않고 입력한 값을 남긴 채 폼 아래에 "예산을 저장하지 못했습니다. 연결을 확인하고 다시 시도해 주세요". 저장 중에는 [저장] 비활성.
- 401: 매물 쓰기 401과 같게 로그아웃 상태로 바꾸고 계정 줄이 "로그인이 끝났습니다"를 보인다. 예산 줄은 기기 예산이 된다.
- 로그아웃: 계정 예산 캐시를 지우고 즉시 기기 예산을 보인다.

## 수용 기준

확인 방법: 리드가 화면(360×780, 로컬 `wrangler dev` 또는 미리보기), `curl`(쓰기 요청에 `-H 'Origin: <같은 origin>'`), `wrangler d1 execute ... --command "SELECT id, budget FROM users"`로 확인한다. 새 테스트는 쓰지 않고 `pnpm lint`·`pnpm format:check`·`pnpm test`·`pnpm build`가 통과한다.

- [ ] AC-0 (배포 후 기존 데이터·주소 그대로, 최우선): 배포 전 main 빌드로 매물·메모·예산·작성 중 입력·실거래가 시군구를 넣은 브라우저 프로필에서 새 빌드를 열면, 로그인하지 않아도 전과 같이 보이고 정렬도 전과 같다(기억 키가 없으면 자기자금 적은 순·상세히). 로그인 상태의 서버 매물도 그대로다. 개발자도구에서 `loan-calculator/listings`·`budget`·`draft`·`trade-lookup` 값이 배포 전과 바이트 단위로 같고(로그인·로그아웃·예산 이전·로그인 중 예산 수정 뒤에도), 새로 생긴 키는 `listings-view`·`budget-imports`뿐이다. 마이그레이션 뒤 D1 `listings`·`sessions` 행 수가 전과 같다. 옛 주소 `#/listings`, `#/listings?sort=recent`, `#/listings?sort=name&view=compact`, `#/listings?sort=foo`가 모두 오류 없이 열리고, 기억 키가 없는 브라우저에서 각각 자기자금 적은 순·최근 저장 최신순·가나다 가→하 간단히·자기자금 적은 순으로 보인다.
- [ ] AC-1 (방향 전환): 이름·가격이 다른 매물 3개와 자기자금 미확인 매물 1개가 있을 때, [자기자금순]을 누를 때마다 적은 순 ↑ ↔ 많은 순 ↓로 바뀌고 미확인 매물은 두 방향 모두 맨 뒤다. [최근 저장순]으로 바꾸면 최신 순 ↓로 시작하고 다시 누르면 오래된 순 ↑이다. [가나다순]은 가→하 ↑ ↔ 하→가 ↓이다. 키보드로 선택된 정렬에서 Space를 눌러도 방향이 바뀐다. 화살표는 선택된 버튼에만 있다.
- [ ] AC-2 (주소): 정렬·방향·보기를 바꾸면 주소가 `#/listings?sort=…&order=…&view=…`로 바뀌고 뒤로 가기 이력은 늘지 않는다. 새로고침하면 같은 상태다. 카드를 눌러 계산 화면으로 갔다가 뒤로 가기 하면 같은 정렬·방향·보기와 스크롤 위치로 돌아온다.
- [ ] AC-3 (기억): 가나다순 ↓ + 간단히로 바꾼 뒤 탭을 닫고 `/#/`를 새로 열어 [저장 목록] 탭을 누르면 가나다순 ↓ + 간단히다. 카카오 로그인에서 돌아온 직후(`/#/listings`)와 공유받은 매물 추가 직후도 같다. 개발자도구에서 `listings-view`를 `{"sort":"x","order":"desc","view":"compact"}`로 바꾸고 `#/listings`를 새로고침하면 오류 없이 틀린 필드(sort)만 기본(자기자금순)이 되어 자기자금 많은 순 ↓ + 간단히로 보인다. 시크릿 모드·저장소 차단에서도 화면은 동작한다(기억만 안 됨).
- [ ] AC-4 (예산 API): 로그인 쿠키로 `GET /api/budget` → 200 `{"budget":null}`. `PUT {"budget":30000}` → 200, D1 `users.budget = 30000`, 다시 GET → 30000. `PUT {"budget":null}` → 200, D1 NULL. API 계약의 400 예시 각각 → 400 `invalidParams`, `1`·`999999999` → 200. 쿠키 없이 → 401, `Origin` 없는 PUT/POST → 403. `POST /api/budget/import {"budget":20000}`은 계정이 NULL일 때 200 `{"budget":20000}`, 이미 30000이면 200 `{"budget":30000}`이고 D1 값은 30000 그대로다.
- [ ] AC-5 (브라우저 간 같은 예산): 같은 카카오 계정으로 로그인한 브라우저 두 개(예: 카카오톡 인앱, 사파리)에서, 한쪽에서 예산을 3억으로 저장하면 다른 쪽은 새로고침 또는 창으로 돌아올 때 3억이다. 한쪽에서 비우고 저장하면 다른 쪽도 예산 없음이 된다. 이때 두 브라우저의 `loan-calculator/budget`은 바뀌지 않는다.
- [ ] AC-6 (첫 로그인 이전): (a) 계정 예산 NULL, 기기 예산 2억 → 로그인 후 예산 줄 2억, D1 2억, `budget-imports`에 사용자 id. (b) 계정 3억, 기기 2억 → 3억이 보이고 D1 3억 그대로. (c) (a) 뒤 다른 기기에서 계정 예산을 지운 다음 이 기기에서 다시 열거나 다시 로그인해도 2억을 또 올리지 않는다(예산 없음). (d) 기기 예산이 없으면 아무것도 올리지 않고 기록만 남긴다. 어느 경우든 로그아웃하면 이 기기의 2억(또는 없음)이 다시 보인다.
- [ ] AC-7 (로그인 상태의 로딩·오류): 네트워크를 느리게 하면 예산 줄이 "예산을 불러오는 중"이고 [예산 입력] 버튼이 비활성이며 기기 예산이 먼저 보였다가 바뀌지 않는다. `/api/budget`을 실패시키면(오프라인 등) "예산을 불러오지 못했습니다 [다시 시도]"가 보이고 기기 예산으로 대신 보이지 않는다. 오프라인에서 예산을 저장하면 폼이 닫히지 않고 입력값과 오류 문구가 남는다. D1에서 세션 행을 지운 뒤 예산을 저장하면 로그아웃 상태가 되고 계정 줄이 "로그인이 끝났습니다"를 보인다.

## 가정

- A1: 사파리에서도 같은 카카오 계정으로 로그인해 쓴다(매물은 이미 보인다는 말에서). 로그인하지 않은 사파리는 지금처럼 그 브라우저의 기기 예산을 본다.
- A2: 예산을 지우면(NULL) "계정에 예산 없음"과 구분하지 않는다. 그래서 아직 이전 기록이 없는 다른 기기가 처음 로그인하면 그 기기 예산이 올라갈 수 있다(이미 기록이 있는 기기는 다시 올리지 않음, AC-6c).
- A3: 예산 이전은 매물 이전(`useAccountImport`)과 독립이다. 예산 이전이 실패해도 매물 목록은 보이고, 예산 줄만 오류·재시도를 보인다.
- A4: 예산 이전은 저장 목록 화면에 들어올 때 돈다(예산을 쓰는 화면이 저장 목록뿐이고, 로그인 후 항상 `/#/listings`로 돌아온다). 그래서 이전 훅은 저장 목록 container에 둔다.
- A5: 이전 기록은 사용자 id 단위다. 한 기기를 두 계정이 쓰면 각 계정 첫 로그인 때 그 기기 예산을 각각 올린다(계정이 비어 있을 때만).
- A6: 기억 값은 다른 탭과 실시간으로 맞추지 않는다(다음에 열 때 반영).
- A7: 정렬 방향은 상세히·간단히 두 보기에 같게 적용되고 [목록 공유]도 보이는 순서대로 담는다(지금 `sortedListings`를 넘김).

## 결정 필요

- D1: 계정 예산 D1 저장 위치 — **A `users.budget INTEGER NULL` 컬럼 추가** / B 새 테이블 `budgets(user_id PK REFERENCES users ON DELETE CASCADE, amount, updated_at)` / C 범용 `user_settings(user_id, key, value)`. 추천: A. 이유: 사용자당 값 하나라 1:1 컬럼이 가장 단순하고(조인·행 생성 없음, 계정 삭제 시 함께 사라짐), import가 `COALESCE` 한 문장 UPDATE로 원자적이다. `ADD COLUMN`은 기존 행을 NULL로 두어 AC-0에 안전하다. C는 다음 단계 후보(정렬 기억 동기화)를 위한 추측성 추상화라 지금은 하지 않는다. B는 변경 시각이 필요해질 때(충돌 해결 등) 다시 본다.
- D2: 주소와 기억 중 무엇이 원본인가 — **A 주소에 있는 값이 이기고, 없는 값만 기억으로 채운다. 화면에서 바꾸면 세 값을 모두 주소에 쓰고, 보인 상태를 기억에 쓴다** / B 기억만 원본(주소에서 정렬을 빼고 옛 URL은 한 번 읽어 기억에 반영) / C 기억이 주소보다 우선. 추천: A. 이유: ADR-004의 "정렬은 주소, 새로고침·뒤로 가기에 남음"을 지키고 옛 북마크가 그대로 의미를 갖는다(AC-0). 기본값을 주소에서 생략하면 "기본값을 고른 것"과 "값 없음(기억 사용)"이 구분되지 않아, 클릭 직후 기억의 옛 값으로 되돌아가는 문제가 생긴다 — 그래서 클릭 때는 생략하지 않는다. B는 상태 출처가 하나라 단순하지만 ADR-004를 뒤집고 옛 URL 의미가 사라진다. 채택 시 ADR-004에 보충 기록.
- D3: 방향의 주소 표기 — **A 별도 파라미터 `order=asc|desc`** / B `sort` 값 확장(`sort=name-desc`). 추천: A. 이유: 옛 `sort` 값이 그대로 유효하고, 기준과 방향을 따로 검증·기본값 처리할 수 있다(GitHub API의 `sort`+`direction`과 같은 모양).

## 사용자 확인 필요

- U1 정렬 기본 방향과 화살표: **제안 기본값** — 자기자금순은 적은 순 ↑, 최근 저장순은 최신 먼저 ↓, 가나다순은 가→하 ↑(모두 지금 동작). ↑ = 값이 작은/이른/가 쪽부터. 다른 정렬로 바꾸면 그 정렬의 기본 방향으로 시작한다(정렬마다 전에 쓰던 방향을 기억하지 않음).
- U2 자기자금을 계산할 수 없는 매물(미확인·요건 미충족): **제안 기본값** — 많은 순(↓)에서도 맨 뒤.
- U3 "다시 들어가도 마지막 보던 화면부터"의 범위: **제안 기본값** — 저장 목록의 정렬·방향·보기를 기억한다. 앱을 처음 열 때 계산 화면 대신 마지막 탭(저장 목록)으로 여는 것까지 원하면 다음 단계에서 한다.
- U4 정렬·보기 기억 범위: **제안 기본값** — 기기(브라우저)별. 카카오톡 인앱과 사파리는 각자 기억한다.
- U5 로그인 중 예산과 기기 예산: **제안 기본값** — 로그인 중 바꾼 예산은 계정에만 저장하고 기기 예산은 그대로 둔다. 그래서 로그아웃하면 로그인 전 기기 예산이 보인다. 첫 로그인 때 계정에 예산이 이미 있으면 계정 값을 조용히 쓴다(따로 알리지 않음).
