# LTV 70% 기본값 + 취득세·중개보수를 자기자금에 포함 + 저장 목록 수정·가나다순 + KB시세 입력 보조

작성일: 2026-10-22 · 브랜치(제안): `cony/fees-and-default-ltv`
사용자가 뒤집은 결정: [ADR-006](../decisions/006-extra-costs.md)(부대비용 제외 → 포함), [ADR-009](../decisions/009-borrower-ui.md)·[ADR-013](../decisions/013-ltv-option-rules.md)의 "보수적 기본값"과 "새 계산 시 사용자 지정 끔"(→ LTV 직접 입력 70% 켜짐이 기본). 리드가 이 내용으로 ADR을 새로 써야 한다(아래 "결정 필요" D1~D8과 함께).
관련 결정: [ADR-002](../decisions/002-money-unit.md)(만원 정수. "부대비용이 들어올 때"가 뒤집을 조건이다 → D3), [ADR-004](../decisions/004-routing-state.md)(카드 열기 = draft 교체, `#/listings?sort=`), [ADR-007](../decisions/007-store-inputs-only.md)(입력만 저장), [ADR-012](../decisions/012-custom-ltv-storage.md)(선택 필드 추가 규칙), [ADR-017](../decisions/017-trade-sheet.md)(실거래가 시트), [ADR-018](../decisions/018-integration-test-cap.md)(통합 테스트 8개), [ADR-019](../decisions/019-link-import-excluded.md)(사이트 자동 접근 금지).

테스트 강도: 사용자 요청으로 **최소**로 한다. 새 테스트는 세 가지뿐이다. `calculatePurchaseCosts` 표 테스트(인라인 `it.each`), 기존 `sortListings`·`parseRoute` 테스트 파일에 가나다순 케이스 한 줄씩. 통합 테스트는 추가하지 않는다. 기본값과 자기자금 정의가 바뀌어 깨지는 기존 테스트는 **기대값과 라벨만 고친다**.

## 목표

요청자가 익숙한 방식(매매가·KB시세 중 낮은 금액의 70%)으로 바로 계산되게 하고, 집을 살 때 실제로 드는 취득세와 중개보수까지 넣은 "필요한 자기자금"을 보여 준다. 저장 목록에서는 매물을 "수정"으로 고치고 이름순으로 찾을 수 있게 한다. KB시세는 자동으로 가져올 수 있는 공식 경로가 없으므로, 입력 칸에서 그 사실을 알리고 참고할 실거래가로 바로 갈 수 있게 한다.

## 사용자 시나리오

1. 처음 앱을 열면 "LTV 직접 입력"이 켜져 있고 값은 70이다. 매매가 7억, KB시세 6억 8,000만원을 넣으면 결과 카드에 이렇게 나온다. 적용 LTV 70% 아래에 "규제 기준 40%"(규제지역·무주택), 예상 한도 4억 7,600만원, 매매가 − 예상 한도 2억 2,400만원, 취득세 등 1,286만원(취득세 1.67%·지방교육세), 중개보수 308만원(상한 기준 추정·부가세 포함). 필요한 자기자금은 2억 3,994만원이다.
2. 전용 85㎡를 넘는 집이면 "전용 85㎡ 초과" 스위치를 켠다. 농어촌특별세 0.2%가 더해진다.
3. "새 계산"을 누르거나 스크린샷을 적용하면 LTV는 다시 70%가 되고 85㎡ 스위치는 꺼진다. 소재지와 보유 상태는 그대로 남는다.
4. 보유 상태를 "1주택 미처분(추가구입)", 소재지를 "규제지역"으로 고르면 취득세가 8%(조정대상지역 2주택 중과)로 바뀐다. 결과 카드에 "다주택 중과 8%"가 보인다.
5. 저장 목록의 카드에는 "수정" 버튼이 있다. 누르면 계산 화면이 그 매물 값으로 열리고, 맨 위에 "'래미안 101동' 수정 중"이 보인다. 값을 바꾸고 하단 "변경 저장"을 누르면 저장 시트가 덮어쓰기로 열린다. 값은 그대로 두고 이름만 바꾸려면 배너의 "이름 바꾸기"를 쓴다.
6. 저장 목록 정렬에서 "가나다순"을 고르면 이름순(래미안 2단지 → 래미안 10단지 → 헬리오시티)으로 바뀌고 주소가 `#/listings?sort=name`이 된다. 새로고침해도 유지된다.
7. KB시세 칸 아래에 "KB부동산 앱에서 확인해 입력하세요(자동으로 가져올 수 없음)"와 "이 단지 실거래가 보기" 버튼이 있다. 버튼을 누르면 기존 실거래가 시트가 열린다. 스크린샷으로 단지명을 읽었다면 그 단지로 걸러진 상태다. 시트에는 "실거래가는 KB시세가 아닙니다. 참고용"이 보인다.

## 참고한 사례

- **위택스·시군구 취득세 모의계산**(송파구청 [취득세 계산](https://www.songpa.go.kr/tax/tax_acquisition_house_1_1.html)): 취득세 본세, 지방교육세(본세의 10%), 농어촌특별세(0.2%)를 따로 보여 주고 합계를 낸다. 1세대 1주택만 계산하고, 다주택은 담당 부서에 문의하라고 안내한다. → 세 항목으로 나눠 보여 주는 방식과 "모의계산" 성격의 문구를 가져온다. 다주택은 앱이 아는 경우(1주택 미처분 = 취득 후 2주택)만 계산한다.
- **민간 취득세·중개보수 계산기**([당근 취득세 계산기](https://realty.daangn.com/tools/acquisition-tax) 등): 주택 수, 조정대상지역 여부, 전용 85㎡ 초과 여부, 생애최초 여부를 입력으로 받는다. 중개보수는 "상한요율 기준"이라고 쓰고 부가세를 따로 표시한다. → 입력 항목은 이 관례를 따르되, 주택 수와 조정대상지역은 기존 입력(보유 상태, 소재지)에서 끌어낸다. 새 입력은 85㎡ 스위치 하나다.
- **시군구 중개보수 요율표**(구리시 [부동산 중개수수료 요율표](https://www.guri.go.kr/www/contents.do?key=677)): "거래금액 × 상한요율, 한도액 초과 불가, 부가가치세 별도"로 안내한다. → 계산식과 "부가세 별도" 근거로 쓴다.
- **노트형 목록 앱(Google Keep, 네이버 부동산 관심 매물)**: 카드를 누르면 열리지만, 편집할 수 있다는 것을 카드의 명시적 "수정/편집" 동작과 편집 화면 상단의 "편집 중" 표시로 알린다. → 카드 "수정" 버튼과 계산 화면 배너를 가져온다.
- **목록 정렬의 한국어 이름순**: 연락처·파일 앱은 이름순 정렬에 로캘 비교를 쓴다. 숫자는 자연 정렬이라 "2단지"가 "10단지"보다 앞에 온다. → `Intl.Collator("ko", { numeric: true })`(ECMA-402 표준, 추가 의존성 없음).
- **KB시세 자동 조회 가능성(2026-10-22 확인)**:
  - KB국민은행 [데이터허브 이용가이드](https://file.kbland.kr/image/kbstar/land/pdf/datahub_guide_202307.pdf)(2023-07)의 메뉴는 통계기상도, 통계보드, 부동산지도(AI 추정가), KB통계, 공공통계뿐이다. Open API나 개발자 키 발급 항목이 없다. 데이터허브는 통계 플랫폼이고 단지별 KB시세(일반가)를 API로 주지 않는다.
  - 공공데이터포털(data.go.kr)에서도 KB 단지별 시세 Open API를 찾지 못했다(한국부동산원 통계 API는 KB시세가 아니다).
  - 제3자 상품(예: [Hyphen KB부동산 시세정보조회](https://hyphen.im/product/view?seq=9))은 "스크래핑 방식으로 제공하는 API 상품"이고 기업 대상 유료(월 10만원~)다. kbland.kr는 `User-agent: *` → `Disallow: /`이다(ADR-019 확인). 스크래핑 상품을 쓰는 것은 우리가 간접적으로 자동 접근하는 것이다.
  - `data.kbland.kr/robots.txt`는 `Allow: /`이지만, 화면이 부르는 내부 엔드포인트(`data-api.kbland.kr`)는 문서화되지 않은 비공식 경로다. ADR-019의 "공개 API가 없어 예고 없이 깨진다"에 해당한다.
  - → **KB시세는 가져오지 않는다(ADR-019 유지).** 입력 보조(D8)만 한다.
- **호갱노노·아실 등 실거래가 앱**: 단지 화면에 최근 실거래가와 시세를 나란히 보여 주되 출처를 구분해 표시한다. → 실거래가는 "참고용, KB시세 아님"으로 구분해 보여 준다.

## 범위

- 포함:
  - LTV 직접 입력의 기본값을 켜짐 + 70으로 바꾼다(처음 열기, 새 계산, 스크린샷 적용). 규제 기준 LTV는 지금처럼 적용 LTV 줄 아래에 나란히 보여 준다(D1).
  - 취득세(본세 + 지방교육세 + 농어촌특별세)와 중개보수(상한 기준, 부가세 포함)를 자동으로 계산해 필요한 자기자금에 더한다. 결과 카드, 요약 바, 목록 카드, 자기자금순 정렬이 모두 같은 값을 쓴다.
  - 세율과 요율은 새 상수 파일에 기준일과 출처를 붙여 모은다. 확인되지 않은 셀은 `null`로 둔다(D2).
  - 입력 하나 추가: "전용 85㎡ 초과" 스위치. 저장 매물에는 선택 필드로 넣는다(D4, ADR-012 규칙).
  - 저장 목록 카드의 "수정" 버튼, 계산 화면의 "OO 수정 중" 배너와 "이름 바꾸기", 편집 중 저장 버튼 라벨 "변경 저장"(D7).
  - 저장 목록 "가나다순" 정렬(`sort=name`).
  - KB시세 입력 보조: 안내 문구와 기존 실거래가 시트로 가는 버튼, 시트의 "KB시세 아님" 문구(D8).
- 범위 밖:
  - KB시세 자동 조회(공식 API 없음, ADR-019). 스크래핑 기반 제3자 API도 쓰지 않는다.
  - KB시세 기기 기억(단지·면적별 자동 채움). D8 다음 단계 후보.
  - 생애최초 취득세 감면의 계산 반영. 안내 문구만 둔다(D6).
  - 등기 관련 비용(법무사 보수, 국민주택채권 할인, 인지세), 이사비, 대출 부대비용(인지세·보증료)
  - 3주택 이상, 법인, 분양권·오피스텔, 공시가격 1억(지방 2억) 이하 주택 중과 제외, 지방 미분양 감면, 인구감소지역 특례
  - 시·도 조례별 중개보수 요율 차이, 간이과세자 중개사(부가세율이 다름), 중개보수 협의 금액 직접 입력
  - 2026년 지방세제 개편안(2026-08-26 발표, 입법예고 단계): 생애최초 40세 미만 300만원, 일시적 2주택 처분기한 단축 등. 국회 통과 전이라 반영하지 않는다.
  - 규제 기준으로 계산한 예상 한도와 자기자금을 한 벌 더 보여 주기(다음 단계 후보)

## 세율·요율 (2026-10-22 확인)

law.go.kr 조문 본문은 자동 조회로 열리지 않았다(JS 렌더링). 그래서 조문은 법령 미러(korea.legal)로 읽고, 숫자는 시군구 공식 안내 페이지와 대조했다. "대조" 열이 그 상태다. 미확인 셀은 구현에서 `null`이다.

### 계산 함수

`src/lib/utils/calculatePurchaseCosts.ts`(새 파일, 순수 함수)

```ts
calculatePurchaseCosts(input: LoanInput, regulations: Regulations): PurchaseCosts
type PurchaseCosts =
  | { status: "ok";
      acquisitionTax: { rateBp: number; isHeavy: boolean; tax: number; localEducationTax: number;
                        ruralSpecialTax: number; total: number };   // 만원, 항목별 올림
      brokerageFee: { rateBp: number; isCapped: boolean; fee: number; vat: number; total: number };
      total: number }
  | { status: "unconfirmed"; reason: "heavyRuralSpecialTax" }       // 중과 + 85㎡ 초과
```

- 주택 수 유도: `oneHomeKeep` → 취득 후 2주택. 나머지(무주택 3종, `oneHomeDisposal` = 일시적 2주택) → 일반세율. 중과는 `oneHomeKeep && region === "regulated"`일 때만이다(가정 A1, A2).
- 6~9억 세율: `rateBp = Math.round((salePrice − 45000) / 150)`. `(가액 × 2/3억 − 3)%`를 bp로 바꾼 식이다(가정 A3).
- 원 단위 계산: 본세 원 = `salePrice × rateBp`. 지방교육세 원 = 일반은 본세의 10%, 중과는 `salePrice × 40`. 농특세 원 = `salePrice × 20`. 중개보수 원 = `min(salePrice × rateBp, maxFee × 10000)`, 부가세 = 보수의 10%. 각 항목을 **만원으로 올림**하고 합계는 올림한 항목의 합이다. 화면에서 항목을 더하면 합계와 맞는다(D3).
- `calculateLoan`은 이 함수를 부른다. `LoanResult` 공통부에 `purchaseCosts`를 더한다. 한도와 무관하므로 `unconfirmed`/`ineligible` 상태에서도 계산한다. `ok` 상태에 `downPayment = salePrice − loanLimit`을 더하고, `ownFunds = downPayment + purchaseCosts.total`로 바꾼다. 부대비용이 `unconfirmed`면 `ownFunds: null`이다(타입을 `number | null`로 넓힌다. 정렬은 이미 null을 맨 뒤로 보낸다).

## 화면

1. **계산 화면 입력부**
   - "LTV 직접 입력" 스위치: 라벨을 "LTV 직접 입력(기본 70%)"으로 바꾼다. 처음 열면 켜짐·70이다. 끄면 규제 LTV로 계산한다. 다시 켜면 빈 칸이 아니라 70을 채우고 포커스를 주며 전체 선택한다. 은행 상담값을 바로 덮어 칠 수 있다.
   - "전용 85㎡ 초과" 스위치(새 입력): LTV 직접 입력 위에 둔다. 기본은 꺼짐이다. 보조 문구는 "농어촌특별세(0.2%) 계산에 씁니다"이다.
   - KB시세 칸 아래 보조 줄(D8): "KB부동산 앱에서 확인해 입력하세요(자동으로 가져올 수 없음)" + 텍스트 버튼 "이 단지 실거래가 보기". 버튼은 기존 실거래가 시트를 연다(같은 `sheet.open("trades", …)`, 포커스 복귀 대상은 이 버튼). 기존 결과 카드 아래 "이 지역 실거래가 보기" 버튼은 그대로 둔다. 기준 금액 줄(`CollateralBaseLine`)과 겹치지 않게 그 위에 둔다. 오류 문구가 있으면 오류가 먼저다.
2. **실거래가 시트**: 머리에 한 줄 "실거래가는 KB시세가 아닙니다. 참고용으로만 보세요"를 더한다. 조회·필터 동작은 바꾸지 않는다.
3. **결과 카드** (계산 과정을 숨기지 않는다)
   - 줄 순서: 기준 금액 → 적용 LTV(규제 기준 n% 병기, 지금 그대로) → LTV 금액 → 한도 상한 → 예상 한도 → **매매가 − 예상 한도** → **취득세 등**(값은 합계, 아래 줄에 "취득세 1.67% 1,169만원 · 지방교육세 117만원 · 농어촌특별세 비과세(85㎡ 이하)". 중과면 "다주택 중과 8%") → **중개보수**(값은 부가세 포함 합계, 아래 줄에 "상한 0.4% 기준 추정 · 부가세 10% 포함") → **필요한 자기자금**(강조, 라벨에서 "(부대비용 제외)"를 뺀다).
   - 무주택·생애최초면 취득세 줄 아래에 "생애최초 감면 대상이면 최대 200만원 줄어듭니다(미반영)"를 둔다.
   - 하단 범위 문구: "DSR·소득 심사 미반영. 등기 비용(법무사·채권·인지세)은 제외".
   - 부대비용이 미확인이면(중과 + 85㎡ 초과): 취득세 등 "—", 상태 문구 "다주택 중과 시 농어촌특별세는 1차 출처로 확인되지 않아 계산하지 않습니다", 필요한 자기자금 "—".
   - 근거 보기(`RegulationBasis`): "취득세"와 "중개보수" 항목을 더한다. 출처 링크, 시행일, "세율 기준일 2026-10-22"를 적는다.
   - 매일 쓰는 사람의 불편: 기본값이 늘 켜져 있어 규제지역에서는 "규제 LTV보다 높습니다" 경고가 매번 보인다. 경고 문구를 "실제 대출은 규제 기준(n%)으로 나올 수 있습니다"로 바꿔 한 줄로 유지한다. 요약 바 태그 "사용자 지정 LTV 70%"는 지금처럼 보인다(지금 계산이 무엇을 전제로 하는지 스크롤 없이 알 수 있다).
4. **스크린샷 시트 미리보기**: "사용자 지정 LTV는 꺼집니다"를 "LTV는 기본 70%로 돌아갑니다"로 바꾼다. 지금 값이 이미 70이면 보이지 않는다.
5. **저장 목록**
   - 정렬: `ChoiceGroup` 선택지 3개 "자기자금순 / 최근 저장순 / 가나다순"(`columns={3}`). 360px에서 세 칩이 한 줄에 들어가야 한다. 바꿀 때 히스토리를 쌓지 않는다(`location.replace`, 지금 규칙).
   - 카드: 삭제 옆에 "수정" 버튼을 둔다. 동작은 카드를 누를 때와 같다(draft 교체 후 `#/`로 이동, ADR-004). "필요한 자기자금"은 부대비용을 포함한 값이다. 이름이 길어도 두 버튼이 360px에서 한 줄에 들어가야 한다.
6. **계산 화면 편집 배너**(편집 중일 때만, `findDraftListing`이 매물을 찾을 때): 제목 아래 "'래미안 101동' 수정 중" + 보조 버튼 "이름 바꾸기". "이름 바꾸기"는 저장 시트를 덮어쓰기 모드로 연다. 입력이 저장본과 같아 저장 버튼이 "저장됨"(비활성)인 상태에서도 열린다. 지금은 입력이 같으면 이름만 바꿀 방법이 없다. "새 계산"을 누르면 배너가 사라진다(연결 해제, 지금 동작).
7. **요약 바 저장 버튼**: 편집 중이고 변경이 있으면 라벨이 "변경 저장"이다. 누르면 지금처럼 저장 시트(주 버튼 "덮어쓰기", 보조 "새로 저장")가 열린다.
   - 매일 쓰는 사람의 불편: 뒤로 가기로 목록에 돌아가면 스크롤 위치와 정렬(주소)이 복원된다(기존). 다른 탭에서 매물을 지우면 배너가 사라지고 저장은 "새로 저장"으로 돌아간다(기존 `notFound` 처리 그대로).

## 가정

- A1: "1주택 미처분(추가구입)"은 취득 후 1세대 2주택이다. 앱은 2주택 이상 보유자를 다루지 않는다. "1주택 처분조건부"는 일시적 2주택(중과 제외)으로 보고 일반세율을 쓴다. 처분 기한은 표시하지 않는다.
- A2: 앱의 "규제지역"은 조정대상지역이다. 10·15 대책(S2)으로 서울 전역과 경기 12곳이 조정대상지역·투기과열지구로 함께 지정됐고, 2026-07-01 추가 지정(S4)도 같은 규제지역으로 본다. 수도권 비규제·비수도권은 비조정이다. 취득세 중과는 사는 주택의 소재지 기준이라 기존 `region` 의미("구입 대상 주택 소재지")와 맞다.
- A3: 6~9억 세율의 반올림은 "× 1/100"까지 적용한 값(0.0167)을 소수점 넷째 자리로 맞춘다. 즉 퍼센트로는 둘째 자리(1.67%, 167bp)다. 흔히 쓰이는 예시(7억 1.67%, 8억 2.33%)와 맞는다. 1-0에서 원문으로 확정한다.
- A4: 취득세 과세표준은 매매가다. 시가표준액(공시가격)이 더 높은 드문 경우는 다루지 않는다.
- A5: 농특세 비과세 기준은 전용 85㎡ 하나만 쓴다. 수도권 밖 읍·면 100㎡ 예외는 범위 밖이다.
- A6: 중개보수 요율은 전국이 별표1과 같다고 본다(구리·인천 확인. 2021 개정에서 조례 가감 조항이 빠졌다). 거래금액은 매매가다.
- A7: 기존 저장 draft는 새 필수 필드 때문에 한 번 기본값으로 초기화된다. 저장 목록은 영향이 없다.
- A8: 70은 규제 값이 아니라 사용자 기본 입력값이다. 한도 상한은 지금처럼 사용자 지정 LTV에도 적용한다(ADR-013 유지).
- A9: "규제 LTV(기존 계산)를 나란히"는 지금 화면의 "규제 기준 n%" 병기를 뜻한다고 본다. 규제 기준 한도·자기자금을 한 벌 더 보여 주는 것은 다음 단계 후보다.
- A10: 가나다순은 `numeric: true`로 숫자를 자연 정렬한다(리드 지시의 `Intl.Collator('ko')`에 옵션 하나를 더했다). 단지 번호가 들어간 이름이 흔해서다. 영문은 한글 뒤에 온다(ko 로캘 기본).
- A11: 요청자의 "KB시세는 고정인데"는 "공표된 값이니 앱이 찾아 줄 수 있지 않느냐"는 뜻으로 읽는다. 같은 단지의 여러 매물을 비교할 때 같은 KB시세를 반복해 넣는 불편이 핵심일 수 있다. 이 불편은 D8 A(기기 기억)가 직접 푼다.

CLAUDE.md의 "한 파일에 모은다"는 "종류별로 한 곳"으로 해석한다(대출 규제 한 파일, 부대비용 한 파일).
- D3 금액 단위(ADR-002 뒤집을 조건 도달): A 입력·표시·저장은 만원 정수를 유지하고, 세금·보수는 bp 세율로 원 정수까지 계산한 뒤 항목별로 만원 올림, 합계는 올림한 항목의 합 / B 만원에서 바로 계산하고 내림 / C 전부 원 단위로 전환 — 추천: A. 이유: 정수 연산이라 테스트로 정확히 고정된다. 9자리 만원 × bp도 2^53 안이다. 올림은 자기자금을 작게 보이지 않게 하는 쪽이다(ADR-009 취지). 항목 합과 합계가 화면에서 맞는다. C는 저장 형식과 입력 UI를 모두 바꾼다.
- D4 취득세 입력: A 주택 수·조정대상지역은 기존 입력에서 끌어내고, "전용 85㎡ 초과" 스위치 하나만 추가한다(기본 꺼짐, 저장은 선택 필드) / B 새 입력 없이 항상 85㎡ 초과로 보고 계산한다(농특세 0.2% 과대) / C 새 입력 없이 85㎡ 이하로 고정하고 문구로 알린다 — 추천: A. 이유: 차이가 매매가의 0.2%(10억이면 200만원)라 무시하기 어렵다. 입력 하나로 정확해지고, 다음 단계에서 OCR 면적으로 자동 설정할 수 있다.
- D5 중개보수 부가세: A 10% 포함(일반과세자 기준, 문구로 표시) / B 제외하고 "부가세 별도" 문구 / C 포함 여부 스위치 — 추천: A. 이유: 자기자금은 실제로 내는 돈이어야 한다. 중개사무소 대부분이 부가세를 받는다는 것은 확인한 것이 아니라 가정이므로 문구로 드러낸다. 상한 기준이라 이미 넉넉한 추정이다.
- D6 생애최초 감면: A 계산에 넣지 않고 "최대 200만원 줄어들 수 있음(미반영)" 안내 / B 본세에서 min(본세, 200만원)을 뺀다 / C 지방교육세 감면과 감면분 농특세까지 정밀 계산 — 추천: A. 이유: 앱의 "생애최초"(대출 기준)와 세법 요건(본인·배우자 소유 이력, 본인 거주, 3년 추징)이 같다고 보장할 수 없다. 감면 시 부가세 처리를 1차 출처로 확인하지 못했다. 미반영은 자기자금을 크게 보이게 하는 방향이라 안전하다.
- D7 목록에서 수정: A 계산 화면 편집 배너와 "변경 저장" 라벨만 추가(카드 동작은 그대로) / B A + 카드의 "수정" 버튼 + 배너의 "이름 바꾸기" / C B + 저장 버튼이 시트 없이 바로 덮어쓰고, 이름 변경은 목록 카드의 작은 시트로 — 추천: B. 이유: 요청자가 못 찾은 것은 "수정할 수 있다"는 신호다. 보이는 버튼과 편집 중 표시로 해결된다. 흐름은 ADR-004(draft 교체)를 그대로 쓴다. 지금은 입력이 같으면 저장 버튼이 "저장됨"으로 비활성이라 이름만 바꿀 방법이 없는데, "이름 바꾸기"가 이 구멍을 막는다. C의 바로 덮어쓰기는 되돌리기가 없어 실수로 덮을 위험이 있고, "새로 저장" 선택지가 숨는다.
- D8 KB시세 "검색해서 가져오기" 요청의 대안(자동 조회는 공식 API가 없어 하지 않는다, ADR-019 유지): A 단지명 + 전용면적별로 사용자가 한 번 넣은 KB시세를 기기에 기억해, 같은 단지·면적을 다시 고르면 자동으로 채운다(스크린샷 OCR 단지명·실거래가 시트 단지명과 연결) / B 기억 없이 입력 칸에 "자동으로 가져올 수 없음" 안내와 기존 실거래가 시트로 가는 버튼만 둔다(실거래가는 "KB시세 아님"으로 명시) / C A와 B 둘 다 — 추천: **이번 실행은 B, A는 다음 단계 후보.** 이유: (1) A의 키가 될 단지 식별 정보가 지금 앱에 없다. 저장 매물에는 자유 입력 이름만 있고, 단지명은 OCR 추정값(U5 실제 스크린샷 검증 전)과 실거래가 필터 문자열뿐이다. 키가 틀리면 다른 단지의 KB시세가 조용히 채워져 한도를 잘못 보여 준다. (2) KB시세는 주 단위로 바뀌므로 기억한 값에는 날짜 표시와 만료 규칙이 필요하다. 저장 키·만료·표시까지 하면 이번 범위(태스크 4개)를 넘는다. (3) B는 새 상태와 저장 키 없이 기존 시트를 재사용하고, "왜 자동으로 안 되는지"를 알려 같은 요청이 반복되지 않게 한다. U5로 OCR 단지명 정확도가 확인되면 A를 다음 실행 첫 태스크로 올린다.

## 사용자 확인 필요

없음. 두 목표(70% 기본, 부대비용 포함)와 추가 요청(목록 수정, 가나다순)은 요청자가 명시했다. KB시세는 자동으로 가져올 수 없다는 조사 결과를 요청자에게 전달하는 것은 리드가 한다. 그때 D8 A(같은 단지 KB시세 기억)가 원하던 것인지 물으면 다음 단계 우선순위를 정할 수 있다. 다만 이번 실행의 제품 목표는 바뀌지 않는다. 세법 원문 대조(1-0: 6~9억 반올림, 중과 농특세)는 리드가 할 확인이고, 결과에 따라 해당 셀이 `null`로 남을 뿐이다.
