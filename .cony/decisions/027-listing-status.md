# ADR-027 매물 상태(후보·보류·비후보)의 저장과 변경 경로

- 상태: 채택
- 맥락: 저장 목록에서 매물마다 후보·보류·비후보 상태를 정하고 이름 앞에 보이게 해 달라는 요청. 어디에 저장하고, 목록에서 바꿀 때 어떤 경로로 쓸지 정해야 했다.
- 선택지: A 매물 JSON 선택 필드 `status`, 변경은 메모처럼 전용 PATCH / B 별도 테이블·키(id→상태 맵) / C 전체 PUT으로 덮어쓰기
- 의견: 사용자 속도 요청으로 pm·검토 생략, 리드 판정.
- 결정: A
- 이유: 메모와 같은 성격(목록에서 바로 바꾸는 개인 표시)이라 같은 경로를 쓰면 가장 단순하다. 전용 PATCH라 다른 기기에서 바꾼 가격 등을 되돌리지 않는다(C의 문제). 추가 비용과 같이 선택 필드라 기존 데이터는 키가 없어 그대로다(AC-0). 옛 번들은 모르는 키를 무시한다.
- 규칙:
  - 값: `"candidate"`(후보) | `"hold"`(보류) | `"rejected"`(비후보), 없으면 미지정. 공용 검증(`validateListingFields`)에 추가.
  - 계산 화면 덮어쓰기(PUT·로컬 update)는 메모처럼 기존 상태를 보존한다.
  - PATCH `/api/listings/{id}`는 `{memo}` 또는 `{status}`(null=지움)를 받는다.
- 제품 기본값(사용자 확인 전): 새 매물은 미지정, [복사]는 상태를 넘기지 않음, 공유 링크에는 상태를 빼고 보냄, 이전(import)은 그대로 옮김.
- 뒤집을 조건: 상태별 필터·정렬이 필요해지면 그때 보기 설정에 추가한다.
