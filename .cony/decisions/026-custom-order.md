# ADR-026 직접 정렬(드래그 순서)의 저장 위치와 라이브러리

- 상태: 채택
- 맥락: 간단히 보기에서 꾹 눌러 끌어 순서를 바꾸고, 상세히 보기·서버·다른 기기와 같은 순서로 보이게 해 달라는 요청. 순서를 어디에 저장하고 드래그를 무엇으로 구현할지 정해야 했다.
- 선택지:
  - 저장: A 순서만 따로(로컬 새 키 `loan-calculator/listing-order`, 서버 `users.listing_order` JSON id 배열) / B 매물마다 `position` 필드 / C 로컬은 `listings` 배열 순서 자체
  - 드래그: A `@dnd-kit/core`+`@dnd-kit/sortable` / B 직접 구현(pointer 이벤트)
- 의견: 작은 기능이라 사용자의 속도 요청에 따라 pm 스펙·검토 라운드 없이 리드가 판정했다.
- 결정: 저장 A, 드래그 A
- 이유:
  - 저장 A: 기존 `listings` 키와 서버 매물 행을 전혀 건드리지 않는다(AC-0). 한 번 끌 때 요청이 하나(`PUT /api/listing-order`)라 매물 n개의 position을 고치는 B보다 단순하고 충돌이 적다. C는 순서를 바꿀 때마다 기존 `listings` 원문을 다시 써서 AC-0 원칙(기존 키 재기록 최소화)과 맞지 않는다.
  - 드래그 A: 터치 길게 누르기(지연·허용 거리), 키보드·스크린리더 지원이 검증돼 있다. 직접 구현은 스크롤과 드래그 구분, 접근성을 다시 만들어야 한다(CLAUDE.md: 흔한 기능을 재구현하지 않는다).
- 규칙(제안 기본값, 사용자 확인 전):
  - 정렬에 [직접](`sort=custom`) 추가. 방향 전환 없음.
  - 다른 정렬에서 끌면 지금 보이는 순서로 직접 순서를 만들고 [직접]으로 바뀐다.
  - 순서에 없는 매물(새로 저장·공유로 추가·이전)은 맨 위(최근 저장 먼저). 지워진 id는 무시.
  - 첫 로그인: 계정 순서가 없으면 이 기기 순서를 올린다(계정에 있으면 계정 우선, 예산과 같은 규칙).
- 뒤집을 조건: 매물이 수백 개로 늘어 순서 배열 갱신 충돌이 잦으면 B(fractional index position)를 본다.
