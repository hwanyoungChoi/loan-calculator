# fees-and-default-ltv — QA 검토 (계산 정확성)

날짜: 2026-10-22

## 판정: 조건부 찬성

계산식과 스펙 예시는 손계산으로 모두 맞는다. 다만 경계 테스트가 일부 비어 있고, null 전파 규칙이 한 곳에 하드코딩돼 있어 필수 수정 3개를 붙인다.

## 손계산 검산 (원 단위 = 만원 × bp 규칙)

- 시나리오 1 (7억, KB 6.8억, 70%): 기준 6.8억 x 70% = 47,600. 규제 6억 한도 안. 매매가 - 한도 = 70,000 - 47,600 = 22,400. 세율 round((70,000-45,000)/150) = round(166.67) = 167bp. 본세 70,000x167 = 11,690,000원 = 1,169만. 교육세 10% = 116.9 -> 117. 취득세 등 1,286. 중개보수 70,000x40 = 2,800,000원 = 280, 부가세 28, 합 308. 자기자금 22,400+1,286+308 = 23,994. 스펙과 일치.
- 10억 중과: 본세 100,000x800 = 8,000만. 교육세 100,000x40 = 400만. 농특세(85 초과, 비중과) 100,000x20 = 200만. AC-2 표와 일치.
- 중개보수 AC-3 7개 행(27, 83, 88, 220, 495, 1,155 등) 전부 일치. 올림은 정수 원 기준 Math.ceil(원/10000)이면 보수 올림 후 부가세와 원 기준 부가세가 같다(ceil(ceil(x)/10) = ceil(x/10)). 순서 문제 없음.
- 6억/9억 연속성: 식이 60,000에서 100bp, 90,000에서 300bp로 양 끝에서 평탄 구간과 이어진다. 경계 off-by-one은 결과에 영향이 없지만 의도(이하/초과)는 테스트로 고정할 가치가 있다.
- 반올림 반(half) 케이스: 60,075 -> 100.5 -> Math.round = 101. 법 문구(소수 다섯째 자리 반올림)로 계산해도 0.01005 -> 0.0101(101bp)로 같다. 단 1-0에서 원문 확인 전까지는 가정 A3이다.

## 필수 수정 (최대 3개)

1. AC-3에 구간 경계와 한도 플래그를 추가한다. 현재 5천만, 2억, 12억 경계가 없다. 추가: 4,999(0.6%, 한도 25 적용, isCapped=true) / 5,000(0.5%, 25) / 19,999(0.5%, 한도 80 적용) / 20,000(0.4%, 80) / 119,999(0.5%) / 120,000(0.6%). "이상/미만" 방향을 지키는 것은 9억 한 점뿐이라, 다른 경계가 `<=`로 구현돼도 못 잡는다. AC-2에도 60,000 / 60,001 / 60,075(=101bp) / 90,000 / 90,001 행을 넣는다.
2. 미확인(null) 판정을 상수 값 기준으로 정의한다. 지금 `unconfirmed`는 "중과 + 85 초과"로 하드코딩돼 읽힌다. 1-0에서 `heavyRateBp`가 채워져 분기를 지우면 AC-2 마지막 행이 조용히 사라진다. `ruralSpecial.heavyRateBp === null`일 때 `unconfirmed`로 한다고 스펙에 쓰고, 테스트는 fixture로 `null`을 주입해(스펙이 `as const`를 금지한 이유) 확인한다. 값이 채워진 상수에서는 중과 + 85 초과가 `ok`(농특세 = 채운 값)인 행도 하나 둔다.
3. `ownFunds` 연결을 calculateLoan 수준에서 한 번 고정한다. 새 테스트 3개 제한 안에서 `calculateLoan` 기존 테스트 기대값만 고치더라도, 시나리오 1(23,994)과 `purchaseCosts.status="unconfirmed"` -> `ownFunds === null` 한 행은 반드시 단언한다. 순수 함수 표 테스트만으로는 `downPayment + total` 연결과 null 전파(정렬에서 맨 뒤)를 못 잡는다. 또한 대출 `unconfirmed`/`ineligible` 상태에서 ownFunds가 무엇인지(기존 null 유지) 스펙에 한 줄 적는다.

## 리스크

- A3(6~9억 반올림)과 중과 농특세는 원문 미확인이다. 틀려도 AC-2 표가 같은 가정을 인코딩하므로 테스트는 통과한다. 1-0 결과를 기준으로 기대값을 확정해야 한다.
- 입력이 0 이하이거나 정수가 아닐 때의 동작은 스펙에 없다(상위 검증에 의존). 순수 함수가 NaN을 내보내지 않는지 한 줄 확인 권장.
