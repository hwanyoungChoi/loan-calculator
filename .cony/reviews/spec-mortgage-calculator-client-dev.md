# mortgage-calculator 스펙 — 클라이언트 개발자 검토

날짜: 2026-10-21

## 판정: 조건부 찬성

화면 2개, 순수 계산 함수, 외부 의존성 없음이라는 구조는 실현 가능하고 범위도 적절하다. 다만 아래 "필수 수정" 6건은 구현 전에 스펙에 반영해야 한다. 특히 부동소수점 내림 오류(1번)는 AC-1 계산 정확성을 직접 깬다.

확인한 사실: `package.json`(react 19, vite 8, vitest 5, TS 6, react-query·router 없음), `tsconfig.app.json`(`erasableSyntaxOnly`, `@/` paths 없음), `vite.config.ts`(alias 없음), `src/`(Vite 템플릿 상태), `CLAUDE.md`, `.claude/CONVENTIONS.md`. AC-1의 5개 예시값은 스펙 규칙(D5=C 포함)으로 손계산해 모두 일치함을 확인했다.

## 필수 수정

1. **LTV 곱셈의 부동소수점 오류.** 확인한 사실: Node에서 `Math.floor(90 * 0.7)`은 62이고 정수 연산 `Math.floor(90 * 70 / 100)`은 63이다. 0.4~0.8 구간에서 1~30만 범위의 값 4,676건이 어긋났다. A4가 "곱셈 결과 내림"이라고 정했으므로 이 오류는 한도를 1만원 낮게 보여준다. 수정: `rate`를 정수 퍼센트(`70`)로 저장하고 `Math.floor(base * rate / 100)`로 계산한다. 곱셈 순서를 바꿔서는 해결되지 않는다. 경계 테스트(예: 90, 170, 180)를 AC-1에 추가한다.
2. **Task 1이 입력 검증 없이 화면을 만든다.** `calculateLoan`은 "양의 정수만 받는다"는 전제인데 필드 검증은 Task 3-2다. Task 1 시점에 빈 값·0·소수·음수·너무 큰 값이 들어오면 NaN이나 이상한 결과가 나온다. 수정: 순수 함수 `parseAmount`/`validateAmount`(빈 값 → 빈 상태, 정수 아님/0 이하/상한 초과 → 오류 메시지)를 Task 1로 올리고, 상한(예: 9자리)도 정한다. 현재 스펙에는 최대값이 없다.
3. **금액 입력 컴포넌트가 두 번 만들어진다.** 1-4에서 입력 5종을 만들고 3-1에서 쉼표와 한글 표시를 가진 입력 컴포넌트를 또 만든다. 수정: `AmountInput`과 `formatManwon`(3-1)을 1-4로 옮긴다. 이 앱의 핵심 조작이 금액 입력이고 "모바일 우선"이 목표라 Task 1의 최소 버전에 속한다.
4. **계산 화면의 상태 출처가 모호하다.** `#/listing/{id}`로 열었을 때 draft와 저장 매물 중 무엇을 보여줄지 정해져 있지 않다. 새로고침하면 수정 중이던 draft가 이기는지 저장본이 이기는지, 삭제된 id나 잘못된 해시는 어떻게 하는지도 없다. 사용성 체크리스트도 걸린다. 수정:
   - 불러오기 시 draft를 해당 매물 값으로 대체하고 `listingId`를 draft에 함께 둔다(draft 하나로 통일).
   - 없는 id와 알 수 없는 해시는 `#/`로 replace한다.
   - 불러온 매물에서 값이 바뀌지 않았으면 "저장"/"덮어쓰기"를 비활성화한다.
   - 수정 중 목록으로 이동하면 draft에 남기므로 `confirm`은 불필요하다고 명시한다. 이탈 확인이 필요 없는 이유를 적어 둔다.
5. **보유 상태 UI가 데이터 모델과 어긋난다.** UI는 세그먼트 3개와 "무주택일 때만 활성"인 토글이고, 모델은 `borrower` 4값이다. 비활성 토글은 왜 안 되는지 알기 어렵고, 토글을 켠 채 "1주택"으로 바꿀 때의 처리가 비어 있다. 수정: 4개 선택지(무주택 / 무주택·생애최초 / 1주택 처분조건부 / 1주택 미처분)를 하나의 라디오 그룹(360px에서는 세로 목록 또는 2×2 칩)으로 둔다. 토글과 결합 로직, AC-2의 토글 문구가 사라지고 `borrower` 필드와 1:1이 된다. 소재지·보유 상태의 **초기 기본값**도 정해야 한다(스펙에 없음). 가장 보수적인 "규제지역·무주택(일반)"을 기본으로 하고 화면에 선택 상태가 보이게 할 것을 추천한다.
6. **`useSyncExternalStore` 구현 지침이 없다.** `getSnapshot`이 호출마다 JSON을 새로 파싱하면 참조가 매번 달라져 무한 렌더가 난다(React 19에서도 동일). 수정: 2-2에 "원문 문자열이 같으면 이전 파싱 결과를 재사용하는 캐시, 쓰기 시 구독자 통지, `storage` 이벤트로 다른 탭 반영"을 적는다. `saveListings` 쓰기 실패(`unavailable`) 때 UI에 어떻게 알리는지도 정한다(`error` 토스트 또는 저장 시트 안 오류).

### D3 보완

- `PATHS` 상수를 `src/lib/constants/paths.ts`에 둔다(`#/`, `#/listings`, `#/listing/:id` 생성 함수 포함). 스펙에 없는데 CLAUDE.md 구조 규칙이 요구한다.
- 이 앱에는 `pages/`가 없다. 해시 파서(`useHashRoute`, 도메인 무관)는 `src/hooks/`에 두고, 라우트별 화면 선택은 `App.tsx`가 아닌 얇은 `src/pages/` 또는 `src/AppRoutes.tsx` 한 곳에서 한다. `App.tsx`는 Provider/Layout 자리로 유지한다. 위치를 스펙에서 정해 둔다.
- 타입(`Listing`, `Region`, `Borrower`, `Regulations`)은 `src/lib/types/`로 모은다. 규제 파일을 `as const`로 쓰면 `rate: null` 셀의 타입이 리터럴로 좁아져 AC-4의 fixture 주입이 타입 오류가 난다. 규제 파일은 `Regulations` 타입으로 주석(`satisfies`)하고 `as const`는 쓰지 않는 방식을 정해 둔다.
- 스펙에 `LOAN_REGULATIONS`가 나오지만 데이터 모델에는 `LTV_TABLE`/`LOAN_CAP`/`REGULATION_SOURCES`/`REGULATION_BASE_DATE`만 있다. 이를 묶은 `LOAN_REGULATIONS`를 정의하거나 시그니처를 맞춘다.
- `@/` alias: `tsconfig.app.json`의 `paths`와 `vite.config.ts`의 alias가 모두 필요하다. TS 6에서는 `baseUrl` 없이 `paths`를 쓰는 형태를 우선 확인한다(추론, 1-1에서 `pnpm build`로 검증). vitest는 vite 설정을 공유하므로 테스트에서도 동작해야 한다.
- 컨벤션의 "react-query 커스텀 훅" 규칙은 HTTP가 없는 이 프로젝트에 적용되지 않는다. 스펙에 "react-query·axios 미도입, 저장소는 `useSyncExternalStore`"라고 한 줄 명시해 후속 작업자가 오해하지 않게 한다.

## 범위 관련 의견

- **미확인 처리의 도달 불가 경로.** 현재 스펙의 LTV 행렬 12개 셀은 모두 숫자다. 따라서 "미확인" 배지, "계산 불가" 목록 배지, 맨 뒤 정렬은 실제 데이터로는 나타나지 않는다. CLAUDE.md의 "확인되지 않은 수치는 지어내지 않는다"를 지키기 위해 `rate: number | null` 타입과 `calculateLoan`의 `unconfirmed` 반환은 작아서 유지할 만하다. 그러나 목록 화면의 "계산 불가" 배지와 정렬 분기는 1-2에서 S1·S3 원문 대조 후 실제로 `null`이 남을 때만 만든다. 남지 않으면 Task 2에서 뺀다. (비수도권 생애최초 80%와 "S2에서 유지 확인"으로 채운 70% 두 곳이 간접 근거라 `null`로 남을 가능성이 있다.)
- U1(서민·실수요자 40% → 60%)은 이번 범위 제외에 동의한다. 다만 이 기능이 나중에 추가되면 `borrower`가 4값에서 늘어나 라디오 목록이 길어진다. 라디오 그룹으로 만들면 이때도 선택지 추가만으로 대응된다(5번 근거).

## 사용성 체크리스트 대비 누락

- 저장 성공 후 동작이 없다. 저장하면 계산 화면에 머무는지 목록으로 가는지, 성공 피드백(토스트 등)이 있는지 정한다. 추천: 머물면서 "저장됨" 표시 후 저장 버튼은 비활성(변경 없음).
- 저장 시트의 이름 검증(1~40자)에 현재 글자 수 표시와 blur 시점 오류가 없다. 이름 중복 허용 여부도 정한다(추천: 허용, id로 구분).
- 첫 오류로 포커스 이동: 필드 오류는 입력 중이 아닌 blur/저장 시점에 표시하고, 저장 제출 실패 시 첫 오류 필드로 포커스를 옮긴다. 현재 스펙은 오류 위치만 말한다. 폼 상태는 react-hook-form이 설계 원칙이지만 이 화면은 값이 "즉시 계산"이라 이득이 작다. 입력은 controlled state로 두고 저장 시트의 이름 필드에만 쓰는 편이 가볍다. 도입 여부는 구현자가 정하게 열어 둔다.
- 목록 스크롤 복원은 해시 라우팅에서 브라우저가 해 주지 않는다(화면이 언마운트되어 높이가 사라짐). 방법을 정해야 한다: `sessionStorage`에 스크롤 위치 저장 후 목록 마운트 시 복원, 또는 목록 화면을 계속 마운트해 두고 숨김. 3-2의 "스크롤 복원"이 이 구현 선택을 숨기고 있다. 추천: 목록 화면 언마운트 시 `scrollY`를 모듈 변수나 `sessionStorage`에 저장하고 복원. 목록이 수십 건 이하라 충분하다.
- 목록 최소 높이(버튼 위치가 흔들리지 않게)는 하단 고정 바와 빈 상태 CTA 때문에 의미가 있다. 목록 화면 AC에는 없다.
- 하단 고정 바와 모바일 키보드: `position: fixed; bottom: 0`은 iOS에서 키보드가 올라오면 가려지거나 튄다. `visualViewport` 대응까지 갈지, 키보드가 열려 있을 때는 바를 숨겨도 되는지 정한다(추천: 입력 포커스 중에는 결과 요약이 입력 바로 아래 카드에 있으므로 바는 그대로 두고 키보드가 덮는 것을 허용, 과한 대응 금지).
- 한글 금액 표시는 접근성 면에서 `aria-describedby`로 입력과 연결한다(AC-8 사소한 추가).

## 태스크 분해 / 수용 기준 지적

- Task 1이 가장 크다(규제 파일 + 계산 + 화면 + 검증 + 입력 컴포넌트). 2번·3번 수정을 반영하면 1-4는 더 커진다. 1-4를 둘로 나눈다: 1-4a 입력부(AmountInput, 선택 그룹, 검증), 1-4b 결과 카드·근거 보기·하단 요약 바.
- 의존: 2-3(저장 시트, 목록 화면, 불러오기)은 한 덩어리로 크다. 2-3a 저장 시트와 계산 화면 연결, 2-3b 목록 화면(카드·정렬·삭제·빈/오류 상태)으로 나누면 2-3b와 3-2의 스크롤 복원을 같은 사람이 이어서 할 수 있다.
- 테스트(test 담당) 항목이 시그니처 확정 후 병렬이라고 했으므로, 1-3 시그니처(특히 `ltv` 셀 반환 형태, `cap` 구조, 정수 퍼센트)를 1-1 시점에 타입 파일로 먼저 확정한다.
- AC-1: 정수 퍼센트 경계 케이스 추가(위 1번). `isBoundaryCase`와 D5 결과(구간 판단에 max 사용)를 확인하는 케이스 추가(예: 매매가 160000/KB 140000 → 상한 40000, `isBoundaryCase: true`).
- AC-2: "생애최초 토글" 문구는 5번 수정 시 "4개 선택지 중 선택 시 `borrower`가 대응하는 값"으로 바꾼다. 12개 조합 테스트는 셀이 비어 있는 경우도 잡도록 "region × borrower 전체 조합 순회"로 쓴다.
- AC-3: 상한 경계 `150000`/`150001`/`250000`/`250001`은 좋다. D5=C이므로 매매가와 KB시세가 다른 구간일 때의 경계 케이스를 한 줄 추가한다.
- AC-5: 근거 링크가 `target="_blank"`와 `rel="noopener noreferrer"`를 가진다는 점, S1~S6 URL이 http(s) 형식인지의 무결성 검사를 추가한다.
- AC-6: "손상 데이터" 정의(JSON 파싱 실패, 스키마 불일치, 항목 수준 불일치)를 테스트 케이스로 나열한다. draft는 손상 시 조용히 기본값으로 돌아가도 되는지(리스트와 다른 정책)를 적는다.
- AC-7: "덮어쓰기" 시 `createdAt` 유지·`updatedAt` 갱신, 삭제 후 정렬 유지를 추가한다.
- AC-8: "360px에서 가로 스크롤 없음"은 객관 확인 방법이 없다. 확인 절차(브라우저 개발자 도구 360px에서 `document.documentElement.scrollWidth <= 360`)를 적는다. 입력 `inputMode="numeric"` 외에 쉼표가 들어간 값을 붙여 넣었을 때의 처리도 정한다.
- 누락된 상태: 계산 화면의 `unavailable`(localStorage 접근 불가) 상태에서 draft는 메모리로만 동작한다는 점, 목록 화면 오류 상태에서 "목록 초기화"의 확인 문구.
- 정리 작업: 1-1의 "Vite 템플릿 화면·에셋 제거"에 `App.css`, `index.css`의 템플릿 스타일, `assets/*`, `index.html`의 `lang="en"`→`ko`와 `title`, 존재하지 않는 `/favicon.svg` 링크, 모바일 viewport 확인을 포함한다. 스타일은 CSS Modules 방식을 따르므로 전역 CSS는 리셋과 변수만 남긴다.
