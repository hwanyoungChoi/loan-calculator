# 공유 링크 · 카카오 로그인 동기화 · 로컬 데이터 이전

## 결과

저장 목록·매물을 링크로 공유(값만 복사)하고, 카카오로 로그인하면 어느 기기에서든 같은 목록을 쓰며, 첫 로그인 때 기기의 기존 목록을 계정으로 옮긴다. 로그인하지 않은 사람은 지금처럼 기기에 저장해 쓴다.

## 태스크별 결과

1. 공유 링크 — 완료, PR #19로 먼저 배포
2. 카카오 로그인 + 서버 저장 — 완료(실제 카카오 로그인은 운영에서 확인 필요)
3. 기존 로컬 데이터 이전 — 완료

## 팀이 내린 결정

- [ADR-023](../decisions/023-account-sync-share.md): 공유는 D1 스냅샷+토큰, 링크는 해시 라우트, 로그인 상태 목록은 서버 원본+react-query, 서버 매물은 JSON 본문, 세션은 D1. **검토 권장**: D3(로그인 상태에서는 서버가 원본, 오프라인 쓰기 없음)

## 수용 기준

- AC-0 기존 데이터 보존(최우선): 통과 — 기존 키 4개는 이름·형식·읽기 판정 그대로, 지우거나 다시 쓰지 않음. 새 키는 `sent-shares`, `session-hint`, `account-imports`. 1차 형식 데이터가 로그아웃 상태에서 그대로 보이는 것을 리드가 화면으로 확인, 로그인·이전·로그아웃 전 과정에서 로컬 원문 불변(fe 헤드리스)
- AC-1~5 공유: 통과(PR #19)
- AC-6 키 없음, AC-8 서버 검증·상한: 통과(be curl)
- AC-7 실제 카카오 로그인: **미검증** — 운영에서 사용자와 확인
- AC-9·10 여러 기기·충돌·로그아웃: 로컬 D1 세션 흉내로 fe가 확인. 실제 두 기기 확인은 미검증
- AC-11·12 이전·중복 없음: 통과(fe 헤드리스 32항목)
- AC-13: (a) 360px 버튼 통과, (b) 카카오톡 인앱 미검증, (c) 이전 직후 빈 목록 깜박임 없음 통과
- 흐름 규칙 건너뜀 없음. qa는 사용자 지시로 off, 새 테스트 없음, 기존 720개 통과

## 화면 확인

- 확인: 로그아웃 상태 기존 데이터·계정 줄·카카오 버튼(360px), 공유 만들기·받기
- 못 함: 실제 카카오 동의 화면, 카카오 공식 버튼 디자인 가이드(심볼 미포함), 카카오톡 인앱 브라우저

## 사용자 확인 필요

- 운영 카카오 로그인 1회 확인(아래 절차)
- 제안 기본값 U1~U11(스펙): 로그아웃 시 기기 목록으로 복귀, 링크 30일, 메모 기본 제외, 마지막 저장 우선, 자동 이전(다른 계정 기록이 있으면 확인), 로그인 30일 유지, 매물만 동기화
- 개인정보처리방침·탈퇴 기능 필요 여부

## 남은 이슈

- `account-imports` 기록이 깨지면 서버에서 지운 매물이 재로그인 때 되살아날 수 있음
- import 400은 모두 "500개 상한" 문구(직접 고친 id에서만 생김)
- 저장 공간 부족 문구가 실제 원인과 다름, 링크 끊은 뒤 포커스

## 규칙 제안

- 사용자가 "기존 데이터 보존"을 따로 강조했다. 저장 형식을 건드리는 기능에는 스펙에 AC-0(기존 키 불변, 새 키만 추가, 1차 형식 회귀)을 기본으로 넣는 규칙을 `CLAUDE.md`에 둘 것을 제안한다.
