# 주담대 계산기 2차: LTV 옵션과 매물 데이터 가져오기 최종 보고 (2026-10-22)

## 결과

서민·실수요자 우대 조건과 사용자 지정 LTV를 추가했고, 매물 데이터 입력은 두 가지로 줄였다. 국토부 실거래가 조회(첫 서버 코드, Cloudflare Workers + Static Assets)와 네이버부동산 공유 텍스트 붙여넣기 자동 채움이다. 매물 링크를 직접 가져오는 기능은 세 사이트가 자동 접근을 금지해서 하지 않았다(ADR-019).

## 팀이 내린 결정

되돌리기 비싼 결정은 **검토 권장**으로 표시했다.

- [ADR-011](../decisions/011-server-pages-functions.md) 서버는 처음에 Cloudflare Pages Functions로 정했다가, 사용자가 저장소를 Workers로 연결해 **Workers + Static Assets로 개정**했다. 호출 증폭은 캐시와 입력 검증으로 막는다. **검토 권장**: 로직을 `server/`에 분리해 두어 진입점만 바꿨다.
- [ADR-012](../decisions/012-custom-ltv-storage.md) 사용자 지정 LTV는 선택 필드 `customLtvRate?`로 저장한다. ADR-001을 보강해 저장 형식은 선택 필드·enum 추가로만 바꾼다. **검토 권장**.
- [ADR-013](../decisions/013-ltv-option-rules.md) LTV 계산 우선순위는 사용자 지정 → 요건 미충족 → 미확인 → 규제 순이다. 사용자 지정에도 한도 상한을 적용하고, "새 계산"을 하면 사용자 지정을 끈다.
- [ADR-014](../decisions/014-client-http.md) react-query와 fetch 래퍼를 쓰고 자동 재시도는 하지 않는다. ADR-003을 개정했다.
- [ADR-015](../decisions/015-trade-api-format.md) 실거래가는 **기본 자료** API를 JSON으로 받는다. 실제 응답을 확인한 뒤 상세 자료와 XML 처리 안에서 바꿨다.
- [ADR-016](../decisions/016-lawd-codes.md) 법정동코드는 정적 시군구 목록으로 두고, 서버도 같은 목록으로 검증한다.
- [ADR-017](../decisions/017-trade-sheet.md) 실거래가와 붙여넣기는 계산 화면의 시트로 연다. 조회 기억은 draft와 분리한다.
- [ADR-018](../decisions/018-integration-test-cap.md) 통합 테스트 상한을 시나리오 8개로 올린다. ADR-008을 개정했다.
- [ADR-019](../decisions/019-link-import-excluded.md) 매물 링크 가져오기는 하지 않는다. 네이버·호갱노노·KB의 robots.txt가 일반 자동 접근을 금지한다.

## 화면 확인

리드가 360×780 브라우저에서 확인한 것:

- **LTV 옵션**
  - 서민·실수요자 7억/7억: 60%, 한도 4억 2,000만원
  - 8억 5,000만원이면 "요건 미충족"과 이유, 요약 바 태그
  - 사용자 지정 70%: 규제 기준 40% 병기, 경고, 상한 6억
  - 정수 오류
  - 새 계산을 하면 스위치가 꺼짐
- **실거래가**: 로컬 wrangler에 실제 키를 넣고 확인했다.
  - 강남구 3개월 241건
  - "개포자이" 필터를 걸면 2건
  - 닫았다 다시 열어도 재요청 없음
  - 시트 높이 90%
- **붙여넣기**
  - 즉시 미리보기, 적용, KB시세 포커스
  - 이름 제안 "래미안OO 84㎡"
  - 실거래가 단지명 채움
  - 전세 텍스트와 링크만 붙였을 때 안내
- **행정구역 개편 코드**: 실제 API로 확인했다. 광산 12330, 검단 28290, 동탄 41597은 거래가 나오고, 옛 코드는 0건이다.

못 한 것:

- 실기기 키보드·포커스
- 배포 환경에서 Cloudflare IP가 공공데이터포털에 받아들여지는지(A13)
- pages.dev의 Cache API 동작

## 사용자 확인 필요

- **U1**: Cloudflare Worker `loan-calculator`의 Settings → Variables and Secrets에 `MOLIT_SERVICE_KEY`를 Secret으로 등록해야 배포된 사이트에서 실거래가가 나온다. 저장소 연결은 Workers로 되어 있다. 로컬 `.dev.vars`에는 등록했다.
- **U3**: 네이버부동산 공유 텍스트 실제 샘플 2~3개가 필요하다. 받으면 fixture 파일 2개만 추가하면 된다.
- **U4**: 10·15 FAQ 첨부 PDF로 서민·실수요자 60%와 1차 세 칸을 대조해야 한다. 비수도권 서민·실수요자는 지금 "미확인"이다.

## 남은 이슈

- 서비스키가 채팅 기록에 남았다. 개발계정 키지만 원하면 재발급할 수 있다.
- 붙여넣기 매매가는 "매매" 뒤에서 처음 나오는 금액을 읽는다. 예를 들어 "매매 협의 … 관리비 25만원"이면 25를 매매가로 읽을 수 있다. 실제 샘플을 받은 뒤 범위를 좁힌다.
- 실거래가 단지명 필터는 붙여넣기를 적용하면 덮어쓰고, 저장한 뒤에도 남는다.
- 파서가 엄격해서, 업스트림의 한 행이 예상과 다르면(예: `floor`가 정수가 아님) 그 달 전체가 502가 된다.
- 1차 남은 이슈(저장 후 포커스, TabNav의 inert 범위)는 그대로다.
- 다음 단계 후보: 부부 공유 저장(D1 + Access), 매물 원본 링크 저장(서버 요청 없음), DSR, 부대비용.

## 규칙 제안

log의 `놓침`에서 나온 후보다. 지침 파일은 고치지 않았다.

1. **로컬 비밀 파일을 자동으로 읽는 스크립트는 명시적 플래그가 있을 때만 읽게 한다.** backend-dev의 시험 스크립트가 `.dev.vars`를 자동으로 읽어서, 의도와 달리 실제 키로 약 10회 호출했다. hook 후보: `.dev.vars`를 읽는 명령에 경고를 띄운다.
2. **에이전트는 import와 본문을 한 번에 쓴다.** 작성 중에 검증 hook이 "쓰지 않는 import"로 여러 번 실패했다. 이것은 1차의 "임시 파일은 `src/` 밖에" 제안과 같은 계열이다. hook을 바꾸는 후보도 있다: 종료 전 검증을 리드 턴이 아니라 에이전트 작업이 끝난 시점에만 돌린다.
3. **스펙 예시 수치는 경계 상수와 대조한다.** 1차의 floor/round 예시와 2차의 "999억 → null" 예시가 둘 다 상수와 맞지 않았다. `CLAUDE.md` 후보: "경계 예시는 해당 상수로 계산해 확인한 값만 적는다."
