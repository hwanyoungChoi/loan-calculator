# 스크린샷 OCR로 매매가 채우기 최종 보고 (2026-10-22)

## 결과

네이버부동산 앱에는 공유 텍스트 복사가 없어서, 텍스트 붙여넣기를 **스크린샷 OCR**로 바꿨다. 매물 화면을 캡처해 올리면 브라우저 안에서 글자를 읽어 매매가와 단지명을 채운다. 이미지와 인식 엔진 요청은 모두 기기와 우리 사이트 안에서만 오간다.

## 태스크별 결과

| 태스크                                                | 결과                                                                                                                                                |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 스크린샷 → 인식 → 미리보기 → 적용                  | 완료. tesseract.js 7.0.0 + kor, 엔진 파일 자체 호스팅(dist/ocr 5개, 약 5.6MB), 진행·취소, 파서 결함 3건 수정(상태 표시줄 줄, "101동", 공급/전용 쌍) |
| 2. 실사용 다듬기(클립보드 이미지, 실제 스크린샷 튜닝) | 미착수. 실제 앱 스크린샷(U5)을 받은 뒤 진행                                                                                                         |

## 팀이 내린 결정

- [ADR-020](../decisions/020-remove-paste.md) 텍스트 붙여넣기를 스크린샷 OCR로 바꾼다.
- [ADR-021](../decisions/021-ocr-engine-assets.md) tesseract.js 7.0.0 + kor best_int를 쓰고, 엔진 파일은 dist/ocr에 자체 호스팅한다. **검토 권장**: 첫 사용 때 약 5.6MB를 받는다.

## 화면 확인

리드가 vite preview(360px)에서 캔버스로 만든 매물 이미지로 확인했다.

- 0.5초 만에 매매가 "12억 5,000만원"과 단지명 "래미안클래스"를 읽었다.
- 적용하면 매매가 125,000이 들어가고, KB시세가 비워지고, 포커스가 KB시세 칸으로 간다.
- **면적은 실패**했다. ㎡를 "ㅁ"이나 "0"으로 읽었다. 면적은 저장 이름 제안에만 쓰여서 계산에는 영향이 없다.
- 못 한 것: 실제 네이버 앱 스크린샷, iPhone 속도·메모리, Cloudflare 배포 환경.

## 사용자 확인 필요

- U5: 네이버부동산 앱 매물 상세 화면 스크린샷 1~2장(인식률 확인, 면적 보정)
- Cloudflare Worker 이름을 mortgage-fit으로 변경(이름 변경 PR 전에 필요)
- 운영 Worker 시크릿 MOLIT_SERVICE_KEY를 Secret 타입으로 재등록(지금 운영 실거래가 503)

## 남은 이슈

- 면적 인식 실패(㎡ 오인식), 단지명의 O→0 오인식 가능성.
- 준비 중에 취소해도 엔진 내려받기는 끝까지 진행된다(화면은 바로 돌아감).
- ocrSession의 워커 정리에서 terminate 실패 시 처리되지 않은 reject가 남을 수 있다.

## 규칙 제안

- **외부 입력에 기대는 기능은 실제 샘플을 받은 뒤에 착수한다.** 붙여넣기 기능이 "공유 텍스트에 가격이 있다"는 가정 위에 만들어졌다가 통째로 버려졌다. `CLAUDE.md` 후보: "사용자 기기·앱에서 오는 입력 형식은 실제 샘플로 확인한 뒤 구현한다."
