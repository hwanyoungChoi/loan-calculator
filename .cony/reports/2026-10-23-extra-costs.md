# 추가 비용(인테리어·가전·가구)

## 결과

매물마다 인테리어·가전·가구·이사·기타 비용을 줄 단위로 적고, 결과 카드와 저장 카드에 "추가 비용"과 "총 필요 금액(자기자금 + 추가 비용)"을 보인다. 계정 저장·공유·이전에 함께 따라간다.

## 태스크별 결과

1. 엔드투엔드(입력·결과·저장·다시 열기·덮어쓰기) — 완료
2. 저장 목록 카드 — 완료
3. 서버·공유·이전(40개 배치, 413 문구) — 완료. 서버 코드·마이그레이션 변경 없음

## 팀이 내린 결정

- [ADR-024](../decisions/024-extra-costs.md): 계산 화면에서 편집·덮어쓰기 저장, 매물 JSON 선택 필드 `extraCosts`, 공유 128KB 유지, 이전 40개. 검토 권장 없음(되돌리기 쉬움)

## 수용 기준

- AC-0 기존 데이터 보존: 통과 — main 빌드와 새 빌드에 배포 전 형식(1차 형식, 메모, 85㎡, 사용자 LTV, 예산, 키 없는 draft)을 넣고 화면 비교 같음, 원문 불변. 키 없는 매물 [수정]은 "저장됨"·쓰기 0건(로컬·로그인 모두). 키 없는 공유 링크 정상
- AC-1~7: 통과(fe 헤드리스 90항목, be curl). 원격 D1의 40개 최대 크기 import는 미검증
- qa off(사용자 지시), 새 테스트 없음, 기존 720개 통과

## 화면 확인

- 확인: 360px 계산 화면(추가 비용 3줄, 결과 카드 위계), 저장 카드(두 줄·내역 펼침·자기자금 기준 문구)
- 못 함: 실기기

## 사용자 확인 필요

- 제안 기본값 U1~U9(스펙): 예산·정렬은 자기자금 기준, 분류 5개·기본 인테리어, 공유·복사에 포함, 새 계산·저장 후·스크린샷 때 비움, 매물당 30줄·이름 30자, 금액 빈 줄 저장 불가

## 남은 이슈

- draft의 추가 비용 줄 하나가 깨지면 줄 전체를 비움(기존 데이터에는 해당 없음)
- 30개 상한 안내에 스크린리더 알림 없음, 계산 중복(30줄이라 성능 무관), 타입 위치 정리
